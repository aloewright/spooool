# AI Studio Image Generation — ALO-646 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Design verified by the `alo646-grounding` multi-agent workflow (adversarial pass, rev. 2).

**Goal:** Add image generation to the AI Studio: `POST /api/studio/image` (gateway-routed via `@tanstack/ai` `generateImage`) that persists to R2 + `generated_assets` + `ai_costs`, a set-as-thumbnail endpoint, and an `ImagePanel` integrated into the existing `/studio` UI.

**Depends on:** ALO-644 (`studio.ts`), ALO-645 (`studio/` frontend module), ALO-626 (`0022` migration — merged into this branch). Stacked on `alo-645`; `0022` carries `generated_assets` + `ai_costs`.

## Locked decisions (from grounding + open-question resolution)
- **Model:** swap `DEFAULT_IMAGE_MODEL` in `ai-gateway.ts` to GA **`@cf/black-forest-labs/flux-1-schnell`** → emits **JPEG**, so `.jpg` / `image/jpeg` everywhere; flux ignores size (fixed steps) — no `size` param.
- **Gateway:** `gatewayImage` is gateway-binding-only by design — do NOT add a run-gateway branch or change `{ binding }`.
- **Result shape:** `generateImage({ adapter, prompt }) → { images: [{ b64Json }] }`; `b64Json` is raw bytes already base64 — `atob()` directly, null-check (it's a `{url}|{b64Json}` union).
- **Quota:** `getStorageUsage`+`hasRoomFor` precheck (after decode, before put) → 413; generated bytes are quota-invisible today (follow-up).
- **Preview:** endpoint returns the base64 as a `dataUrl` so the panel previews immediately (no public GET route for `studio/images/*`).
- **Set-as-thumbnail:** NEW `POST /api/videos/:id/thumbnail/from-asset` (the existing PUT rejects `studio/images` URLs) that copies the asset into the `thumbnails/{userId}/{videoId}/` namespace and stores an **absolute** `thumbnail_url` (replicate `thumbnails.ts` L143-146).
- **ai_costs** row written; aggregation into cost snapshot/alerts is ALO-650. **STUDIO_GEN_BUCKET** reused (30/hr). **schema.sql** untouched.
